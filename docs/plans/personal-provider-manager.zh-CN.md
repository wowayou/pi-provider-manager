# 个人供应商管理器：重构方案

2026-11-18。供所有者决策的方案，不是已发布的功能清单。本次已完成 Codex 修复和独立静态演示构建；下面的架构迁移、交互改版和公网发布尚未执行。

## 产品决策

保留一个本地工作台、三个原生配置目标。它是我在已有工具之外管理凭据、默认模型、全局提示词和启动命令的备选；平时不运行它，三个 CLI 仍应正常工作。不是聊天客户端、云端密钥库、自动故障转移网关或 CC Switch 的替代全家桶。

最常见的起点应该是**切到一个已存的备用供应商**，而不是重新走三步向导。新建才进向导。打开时先回答三件事：正在看谁的配置、下个会话将用谁、需要我做什么。不新增一个必须经过的仪表盘。

| 日常任务 | 建议交互 | 明确不做 |
| --- | --- | --- |
| 查看或切换已存供应商 | 目标选择器 → 供应商行 → 切换；仅 Pi 要再选模型。成功页写清改变的范围，给可复制命令 | 不复制凭据、不重提整份表单、不顺带改另一端 |
| 新增备用网关 | 保留三步；允许粘贴现有片段，继承已知默认值；最后明确区分「只保存」和「启用」 | 不猜模型协议、不自动探测远端、不默认用真实 key 试发消息 |
| 排查“没有生效” | 在当前设置页就近展示配置目录及来源、原生文件中的模型、适用会话、下一步；读不到或不知道就直说 | 不把“写入成功”称为“网关可用”；不假装看得到用户终端的启动参数 |
| 修改提示词或少量偏好 | 保留独立入口、未保存离开保护和冲突后重新读取；只读链接给出原因 | 不把提示词或凭据同步到公开演示，不自动改写共享文件 |

## 三端的读写契约

| 目标 | 哪个选择是事实 | 切换之后如何使用 |
| --- | --- | --- |
| Pi | 三个原生 JSON；`settings.json` 的供应商 **和模型** 组成默认项，其他供应商仍可用 | 全局默认或精确的模型命令；提示项目配置、已有会话可能不同 |
| Codex | 用户级 `config.toml` 的 `model_provider` 决定选哪张表。仅被选中的受管表对应管理器的「生效中」；私有库记备用项 | 直连用新开的 `codex`；走桥时单独确认桥是否在运行。手写表或内建选择不自动接管 |
| Claude Code | 用户级 `settings.json` 决定全局默认；独立终端启动器固定自己的快照 | 「跟随全局」与「固定此供应商」是两条路径；不把全局默认当作正在运行的终端清单 |

不引入统一供应商数据库，也不跨端同步同名 ID 或 key。一次写入只持有本目标的修订号（标识读到的文件版本），旧版本返回 HTTP 409，禁止静默重试。保留文件权限、读写边界、失败回滚、未知字段和现有跨文件一致性检查。细节以 [架构](../architecture.md) 和[使用手册](../usage.zh-CN.md) 为准。

## 分阶段实施与验收

每一阶段独立提交，沿用既有 HTTP 接口和持久化格式。先有能失败的测试，再移动行为。**无需全做**：如果修完 Codex 已满足日常使用，就停在这里。

| 阶段 | 改哪些地方 | 如何判断可交付 |
| --- | --- | --- |
| 0 · 校准事实（本次） | 修复 Codex 设置、向导、磁盘和私有库对默认模型的分歧；拆开偏好保存与供应商切换 | 外部换模型后保存偏好，真实 CLI 仍请求该模型；手写供应商保持选中；失败不报成功，无凭据回传 |
| 1 · 抽出 Codex 工作流（建议下一步） | 把 `src/App.jsx` 中 Codex 的草稿、保存、激活、成功结果移入目标模块。现有 `src/codex-view.jsx` 只渲染；沿用 `lib/codex-config.mjs`，不换 TOML 解析器 | 同一组接口、文件和浏览器用例迁移前后通过；只保存/启用、409、缺 key、桥失败、外部改文件均覆盖。无文件格式变化，可直接撤回提交 |
| 2 · 收拢公共交互 | 提取三端实际重复的写入锁、请求错误与回读流程；Pi 的模型目录和 Claude 的启动快照仍由各自目标负责。按相同原则拆 `server.mjs` 的路由，但不拆事务 | 两端同时编辑不互相 409；同端旧页面必冲突；失败仍能继续编辑；离开草稿有保护；原有生产浏览器测试不断档 |
| 3 · 缩短备用切换 | 沿用现有橙色浅色主题、深色主题及共享组件；列表直接操作已存项。手机优先保住当前供应商与切换入口，压缩占首屏过多的导航，而非缩小字和按钮 | 以同一份样例记录改前/改后操作数：Codex/Claude 已存项从列表至切换目标不超过两次操作；Pi 允许多一次模型确认。390px/桌面、键盘、空态、等待、缺 key、冲突都实走，日常使用后再决定保留 |
| 4 · 有限自动化与交付 | 优先自动执行本地确定性工作；公开页复用本地界面和样例，独立构建，不把 Node 后端部署到公网 | 启动不访问上游、不写配置；静态站子路径及刷新可用，三端操作不发配置 API 请求；发布包不混入真实路径、日志、凭据或私有库 |

先抽 Codex 而不是先改皮肤，是因为本次缺陷横跨了原生文件、私有库、向导和设置四个位置。只有出现第二个真实共用场景才抽公共逻辑；不建能描述所有目标的通用表单引擎。回退时撤销该阶段的代码或切回上一发布包，不回灌旧配置覆盖用户后续编辑。

## 哪些可以自动做

| 触发 | 默认行为与刹车 |
| --- | --- |
| 打开工作台 | 只读本地配置、识别目录、计算待处理项；不联网、不运行凭据命令、不主动修复 |
| 保存或切换 | 本地校验 → 校验修订号 → 写入 → 回读。锁住重复点击；冲突停下让人选，不循环重试 |
| 检查设置是否有效 | 维护测试用临时目录、假凭据和回环网关自动验证；用户界面默认只报告磁盘事实。真实联通测试不在本轮，若要增加须先确定接收凭据的主机、请求数与费用上限 |
| 运维与兼容 | 保留现有 Pi 更新提醒；不新增定时检查、自动安装、自动拉起桥或真实模型健康探测。验证版本变动仍需人工确认 |

## GitHub 展示交付

参考 [pi-web 的演示说明](https://github.com/agegr/pi-web/blob/main/demo/README.md)：借用“真实组件、浏览器样例、无模型调用”，不搬它的会话、终端和文件浏览。本次阅读了仓库及演示实现说明，未验证对方站点的具体交互。

本项目可用 `npm run build:showcase` 生成 `artifacts/showcase/`。只发布**这个目录的内容**：不需要也不能部署 `server.mjs`、整个 `artifacts/`、`.env`、上层目录或本机配置。展示构建强制使用内存样例，页上标明不要输入真实密钥；浏览器内容安全策略禁止网络连接和表单提交。刷新丢弃演示编辑，主题偏好仍可保存在浏览器。日常本地版和 Sites 打包命令不变。

**发布是单独的授权点。** 本次不推送、不改 Pages 设置、不开 GitHub Actions。首选一次手动发布；公开前核对仓库可见性、账户计划及 [Pages 限额](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)，检查文件清单和站点子路径。若以后选择 Actions，应先核对账户剩余额度和计费，再单独批准：仅手动触发、每次一个任务、超时 5 分钟、无自动重试、并发上限 1；发布失败保留旧版，不启用付费回退。未确认成本前不创建工作流。

**停止条件：** 没有真实场景可以证明一个新操作省事，就不加；不能解释某次写入会改谁的原生文件，就不执行；不能保证公开页与本机配置隔离，就不发布。
